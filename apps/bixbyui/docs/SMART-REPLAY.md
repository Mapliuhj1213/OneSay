# 成功路径回放（smart-replay）

手机执行层（`PhoneAgent`）每做一件事都要问好几次模型。很多指令是重复的（「打开设置里的深色模式」「在某 App 里签到」），
上次怎么做成的，这次多半照做就行。本改动在任务**成功**后记下走过的步骤，下次收到同一条指令时先按记下的步骤做，
画面对不上就立刻停下交还模型。

思路参考开源项目 codesfly/phoneDriver（<https://github.com/codesfly/phoneDriver>，Apache-2.0，README「智能回放引擎」与
`replay_engine.py`：成功任务按名字缓存轨迹和每步页面指纹，指纹不符即降级回模型）。
代码按思路自己写，**没有复制其源码**，因此不需要在 NOTICE / THIRD_PARTY_NOTICES 里加条目。
和它的不同：它的指纹是「序号 + 文字 + 描述 + 资源 id」的整屏 SHA-256，要求完全一致；动作按原坐标重放。
这里指纹只看结构与资源 id、按相似度比；节点按特征重新定位，不存编号和绝对坐标；另加了安全规则和连续失败作废。

## 1. 记录

- 键：`sha256(规范化指令 @ 起始 App 包名)`。规范化 = 全角转半角、转小写、去掉空白和标点。没给起始 App 时用开局那屏的前台包名。
  存的是哈希，文件里不出现指令原文。
- 每做成一步（`PhoneAgent.runBatch` 里动作结果不是「失败 / 打不开 / 读回不一致」）记一条：
  - 动作类型与参数（`tap / long / type / scroll / back / home / key / launch / swipe / wait`，方向、包名、按键、等待条件）；
  - 目标节点的稳定特征（`SmartReplay.Target`）：资源 id、类名、名字（文字 / 描述；「标题 · 摘要」另存标题）、种类（输入框 / 列表 / 开关 / 可点）、
    中心点的**相对位置**（千分比，只作辅助）。**不存编号 `[N]`、不存绝对坐标**；
  - 动作前那屏的**回放指纹**（见第 3 节）；
  - 这一步的敏感判定原因（有的话）。
- 条件没等到的步骤只留动作、去掉条件；模型没做成的步骤不记（它随后会换个做法）。
- 只有任务以 `done` 结束才存。以下情况整次不存（`replayNote` 写明原因）：中途问过用户（回放会悄悄沿用当时的决定）、用户接手过、
  用了「收集列表」、按坐标点（没有节点可定位）、超过 40 步、以及第 4 节的安全情况。
- 回放过的任务不再重录（命中后模型补的步骤不并进路径；降级后模型做成的也不覆盖旧路径——旧路径按连续失败规则处理，作废后下一次成功会重新记）。

## 2. 回放

再收到同键指令（开局打开 App 之后）：

1. 读稳定画面（`StableRead`；`settle` 开着时上一步动作后读到的已经是稳定画面，不再多读；关着时用默认参数单独稳定读一次）；
2. 看有没有弹窗：录制时不在的弹窗按钮（允许 / 拒绝 / 我知道了 / 跳过 / 以后再说 / 立即更新 / 取消…）或对话框资源 id（`alertTitle`、`button1`、`permission_*`、含 dialog / popup / alert 的 id）出现了 → 停；
3. 比回放指纹：前台包名、页面（Activity，两边都有时）必须相同，结构记号集合相似度 ≥ 60%；
4. 用特征重新定位节点：类名、种类、资源 id（有的话）必须一致；名字先比原文，再比「数字换成 #」，再比标题段；
   没名字也没资源 id 的只认原位置附近（短边 8% 以内）的；多个候选时只认原位置附近唯一的那个，否则算**有歧义**；
5. 执行：还原成一步模型指令，走和模型步骤**同一个执行口**（`runBatch`：`PhonePlan.validate` → `SensitiveGuard` / 插件 RiskGate → 宿主确认 → 动作 → 代码侧等待 → 稳定读屏）。

任何一步：弹窗、指纹不符、找不到 / 有歧义、没执行成 / 条件没等到 → 立刻停止，把「回放到第 k 步停下的原因 + 已经做完的步骤（不要重复）」和当前画面交给模型继续（降级），记一次失败；
同一路径**连续失败 2 次作废**（删掉），一次完整回放把失败数清零。
用户拒绝了某一步、用户接手、停止，或走到「输入内容没存原文」的那一步 → 也交还模型，但**不算失败**。

整条走完（命中）后问一次模型确认结果（任务的回答可能依赖当前屏上的内容，比如查到的数值），模型通常直接 `done`。
所以命中时模型调用从 N 次降到 1 次。

## 3. 回放指纹的取舍

stable-screen 的 `UiTree.settleFingerprint()` 是给「画面停没停」用的：结构 + 文字 + 边界 + 状态，任何变化都算不一样。
回放要回答的是「这还是不是上次那个画面」，所以另做了 `UiTree.replayTokens()` / `replayFingerprint()`：

| 看 | 不看 |
|---|---|
| 前台包名、页面（Activity） | 文字（时间、角标数字、列表内容、输入框里的字、摘要） |
| 有资源 id 的元素：「资源 id + 类名」 | 位置与大小（不同机型 / 字号、横幅挤下去） |
| 没资源 id 的元素：「类名 + 可点/输入/滚动/开关」 | 勾选 / 焦点 / 选中状态、元素个数（去重，列表多几行少几行不影响） |

- 记号是 8 位哈希，按集合比 Jaccard 相似度（≥ 0.6），不要求完全一致：页面多了一个角标 view、少了一个推荐位仍算同一画面。
- 代价：**结构相同、内容不同的两个页面分不出来**（例如设置里两个都是「标题 + 列表」的子页）。这由第 4 步「按名字找节点」兜住——
  页面换了，要点的那个名字多半不在，就会降级；真碰巧同名同 id，就会点到。所以敏感步骤一律再确认。
- 没有资源 id 的 App（部分 Compose / WebView 页面）只剩类名记号，指纹区分力很弱，主要靠节点名字定位。
- 文字类弹窗（应用内自绘的「我知道了」）不一定改变结构，所以弹窗另外按按钮文字和对话框 id 判，录制时就在的不算。

## 4. 安全

- 回放的每一步都走原来的敏感判定与确认（同一个 `runBatch`）；录制时判过敏感的步骤，回放时即使现判不敏感也照样确认（`mForceSens`）。
  无执行模式（`headlessHost`）下确认一律拒绝，回放到敏感步骤就停在那里交还模型。
- **不录不放**：指令像付款 / 转账（`SensitiveGuard.PAY` + 转账 / 汇款 / 红包 / 提现 / 还款 / 付款码…）、起始 App 或途中经过的 App 是支付 / 银行 / 钱包 / 密码 / 商店 / 安装器类
  （与 `LinkPolicy.blockedApp` 同一份判定）、任何一步被判为付款 / 下单（含插件按屏上金额判的付款）。回放前也查指令，旧数据里就算有也不放。
- 输入：内容像个人数据（手机号、邮箱、身份证号、连续 4 位以上数字＝验证码 / 卡号）、或输入框是密码 / 验证码栏（`SensitiveGuard.SECRET_FIELD`）、
  或是手机 / 邮箱 / 地址 / 姓名 / 证件 / 卡号 / 账号栏 → **不存原文**，回放到这一步交还模型。密码框本来就不替用户填。
- 节点名字像个人数据（例如联系人显示的是手机号）时只存 SHA-256，定位时对候选算哈希比。
- 指令原文不落盘（键是哈希）。

## 5. 存储与开关

- 文件：应用私有目录 `files/phone_replay.json`（`allowBackup=false`，不上传、不进备份），先写 `.tmp` 再改名；坏文件当空的。
- 最多 200 条，按最近使用淘汰（读到即算使用）；一条路径最多 40 步。
- 开关：偏好 `PhoneHooks.PREF` / `smart_replay`，**开源版默认关**（个人版默认开）；kill 文件 `phone.replay.off` 存在即关；`PhoneHooks.sReplayOverride` 调试覆盖。
  写法与其他功能开关一致（`SmartReplay.decide(override, killed, pref)`）。关着时 `PhoneAgent.replay = null`，行为与改前完全相同（不录、不读、不写文件）。
- 设置：控制台「设置 · 功能 · 替你操作 App」细项页：主开关、「记住成功的步骤，下次直接照做」、已记住条数、「清空记住的步骤」（二次确认后删文件和统计）。
- 统计：`files/phone_last.txt` 多一行
  `replay=… hit=… fallback=… voided=… handoff=… recorded=… replayedSteps=… note=… | paths=… totalHit=… totalFallback=… totalVoided=… totalRecorded=… totalHandoff=…`；
  `Result.trace` 记 `replay start / hit / fallback @k / handoff @k / recorded / not recorded`；Logcat `[PHONE] 回放：…`。

## 需要真机验证

1. 典型重复任务（设置里开关、App 内固定入口）第二次说时是否命中，命中后总耗时和模型调用数。
2. 同一 App 小版本更新、换机型 / 字号 / 横竖屏后，指纹相似度阈值 0.6 是否合适（误降级 vs 误认）；`phone_last.txt` 的 fallback 原因分布。
3. 没有资源 id 的 App（Compose / WebView / 游戏引擎页）上的命中率与误点风险。
4. 应用内自绘弹窗（开屏广告、活动浮层、升级提示）能否被弹窗判定拦下；系统权限弹窗（前台换成权限控制器）是否按「前台 App 不同」降级。
5. 回放到敏感步骤时灵动岛确认卡是否正常弹出；拒绝后模型接手是否顺畅。
6. 动作后转场慢的页面（冷启动、网络加载）下，稳定读 + 指纹比对会不会在转场中途误判不符。
7. Mika 读屏 / 写法插件（`mika.screen` / `mika.dosteps`）开着时本功能整体不录不放（编号与元素表来自另一套实现，未验证），需要时再单独接。
8. 长期使用后文件大小（200 条上限下预计几百 KB 以内）与读写耗时。
