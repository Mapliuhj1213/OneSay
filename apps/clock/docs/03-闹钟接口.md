# 对外闹钟接口（AlarmApiReceiver）

给与 OneSay Clock **同一证书签名**的 App（OneSay 助手）设 / 开关 / 删 / 查闹钟。纯 Java 部分在 `core/AlarmApi.java`（JVM 测试见 `test/.../CoreTest.java` 的 `alarmApi()`），Android 接收器在 `api/AlarmApiReceiver.java`。

## 权限
- 接收器 `com.onesay.clock/.api.AlarmApiReceiver`：`exported="true"`，`android:permission="com.onesay.clock.permission.ALARM_CONTROL"`。
- 该权限 `protectionLevel="signature"`：系统只授予与 Clock 同一证书签名的 App；不内置任何证书指纹。
- 助手清单里 `uses-permission` 并**同名声明**这条权限（同证书可重复声明），所以先装哪个都能授予；签名不同时后装的会因 `INSTALL_FAILED_DUPLICATE_PERMISSION` 装不上。
- 调用方用 `setPackage("com.onesay.clock")` 发**有序广播**，并在调用前核对 `checkSignatures == SIGNATURE_MATCH`。

## 动作与 extras
| Action | extras |
|---|---|
| `com.onesay.clock.action.ALARM_SET` | `hour`(0–23) `minute`(0–59) [`days` 位掩码 bit0=周日…bit6=周六，0=只响一次] [`label` ≤30 字] |
| `com.onesay.clock.action.ALARM_TOGGLE` | `id` `on`(boolean) |
| `com.onesay.clock.action.ALARM_CANCEL` | `id` |
| `com.onesay.clock.action.ALARM_QUERY` | — |

同一时刻、同一重复的闹钟已存在时 `ALARM_SET` 打开它而不是重复新建。调试 / 截图用闹钟（id ≥ 900）不出现在结果里，也不能经接口改动。

## 结果（resultCode / resultData）
- `1` 成功，`2` 参数不对，`3` 找不到这个 id，`4` 不认识的动作；`0` = 没有接收器回应（Clock 版本太旧）。
- resultData（成功和失败都给）：
```json
{"ts":1762480800000,"count":1,"lastId":1,"alarms":[{"id":1,"h":7,"m":0,"d":0,"on":true,"r":"smart","next":1762556400000,"label":""}]}
```
`r` 为 `smart`（智能播报）或 `ring`（只响铃）；`next` 为下次响铃毫秒（关着为 0）。

## 助手一侧
`apps/bixbyui/.../executor/AlarmBridge.java`：Clock 可用走本接口；没装 / 签名不同 / 版本太旧 → 设闹钟交给系统 `AlarmClock.ACTION_SET_ALARM`（`EXTRA_HOUR`、`EXTRA_MINUTES`、`EXTRA_MESSAGE`、重复日 `EXTRA_DAYS`、`EXTRA_SKIP_UI`），没有 App 能接就回「没有设置成功」。
